## source_observation

Agents that operate from conversational history must reconstruct current
operational truth from prior turns.  After external world changes (file edits
made by another process, rebases, dependency updates, stale test caches,
interruptions, or another worker changing a shared contract) the history is
still internally consistent but no longer accurately describes the world.  The
agent then acts on stale assumptions, attempts operations that are invalid in
the true world, or declares completion/blocked incorrectly.  This is an
observation and hypothesis source, not yet evidence.

## hypothesis

An explicit, external, deterministic execution-state surface (condition C2)
produces fewer stale-assumption actions, fewer invalid operations, fewer
incorrect completion decisions, and better recovery correctness than transcript
reconstruction (C0) or generated-summary reconstruction (C1) under identical
perturbations.

Null / explicit non-assumption: the explicit-state design is **not** assumed to
win.  The experiment is structured to falsify the hypothesis if the explicit
state does not outperform the controls on the primary metrics or if its
maintenance cost (secondary metrics) exceeds its correctness gain by the margin
declared in the falsifier.

## falsifier (observable)

The hypothesis is falsified if any of the following is observed across the
P-01..P-12 perturbation suite:

1. C2 fails to outperform C0 and C1 on the primary metrics (stale assumptions,
   invalid operations, incorrect completion decisions, recovery correctness), or
   its advantage is within the noise floor defined by the repetition policy.
2. C2's state-maintenance cost (secondary metrics: duplicate work, repair
   iterations, human intervention, time to objective) exceeds its correctness
   gain by a margin that makes the explicit-state surface net-negative for the
   declared task family.

## system_under_test

The system under test is the **state-reconstruction mechanism**, not a specific
model.  Three conditions are compared:

- **C0 — transcript/history reconstruction**: the agent's state belief is the
  raw sequence of prior actions and observations.
- **C1 — generated-summary reconstruction**: the agent's state belief is a
  deterministic summary generated from the transcript (current step, completed
  steps, last action).  Exact digests are not retained.
- **C2 — explicit execution-state candidate**: the agent's state belief is a
  structured state document with a declared schema:
  - task ledger (step status plus evidence references with state bindings);
  - observed-world sub-digests (base SHA, dependency version, repo digest, test
    result, artifacts);
  - command/effect log.
  The document is updated transactionally after each effect and reconciled
  against the true world before each action.

All three conditions use the same deterministic scripted policy surface and
step budget.

## primary_metrics

Operational definitions are implemented in `metrics.py`; this section is the
human-readable source of intent.  Counting rules operate over the per-cell run
log (JSONL) produced by `harness.py`.

- **stale_assumptions_acted_upon**: count of log events where the agent's
  reconstructed belief digest at action time differs from the true world digest
  at action time (`belief_digest != world_digest`).  One event counts at most
  once.
- **invalid_operations_attempted**: count of log events whose action is in the
  oracle's `invalid_actions` set for that perturbation.
- **incorrect_completion_decisions**: count of `declare_done` events when not
  all six acceptance checks are satisfied, plus count of `declare_blocked`
  events when all six acceptance checks are satisfied.
- **recovery_correctness**: for each cell, 1 if the first post-perturbation
  action matches the oracle's condition-specific `expected_recovery_action`,
  else 0.  Aggregated as count and rate per condition.

## secondary_metrics

- **duplicate_work_events**: actions that repeat an effect already reflected in
  the true world and command log (e.g., updating the dependency when it is
  already at the target version).
- **repair_iterations**: actions whose purpose is to re-observe or repair state
  (`inspect_*`, `check_base_sha`, `run_tests`, `reset_artifacts`,
  `reverify_evidence`, `reconcile`).
- **token_consumption**: recorded as `not-observed` for the deterministic pilot;
  no estimation is performed.
- **human_intervention_events**: count of `declare_blocked` actions.
- **time_to_objective_completion**: number of turns (step counts, not wall
  clock) until all six acceptance checks are satisfied; `null` if not reached
  within budget.

## repetition_policy

The pilot is deterministic, so the repetition policy is **run-twice digest
equality**: `build_fixture.py` reproduces the same `fixture_digest`, and
`harness.py determinism-check` reproduces the same `run_digest` across two
isolated runs.

Future model-in-the-loop runs will declare the number of repetitions, the seed
policy, and the statistical aggregation method in a new protocol version.  They
are not in scope for this pilot.

## seed_policy_if_relevant

Fixture generation uses fixed constants.  No PRNG is required; if a future
version introduces randomness, the seed will be fixed and recorded in the
fixture manifest.
