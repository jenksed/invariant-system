# WP-09 Lane 6 — Adversarial Review Checklist

Date: 2026-08-19. Pre-authored alongside the WP-09 implementation so
the adversarial review (Lane 6) has a structured checklist from day
one. The reviewer MUST find file:line or execution evidence for each
finding.

This checklist mirrors the WP-09 Section 18 items exactly.

---

## 1. Temper becoming authority

- [ ] No Temper code path produces an authoritative transition.
  Check:
    - `products/temper/src/client.ts` — only sends RPCs; never mutates
      Kiln state directly.
    - `products/temper/src/live.ts` — `canonicalToModel/1` only
      DERIVES a `WorkbenchModel` from the daemon response; it does not
      cache authoritative state.
    - `products/temper/src/stream.ts` — `processNotification/1` only
      triggers `onResync` which calls `project.open` again.
- [ ] No Temper code path treats a green HTTP 200 as a domain success.
- [ ] No Temper code path bypasses the daemon to apply patches,
  approve, or submit HumanDecision.

## 2. RPC success treated as domain success

- [ ] `Kiln.RPC.Handlers.Patch.handle/3` journals intent BEFORE
  `PatchService.apply/3` and observation AFTER (P2 contract).
- [ ] `verify.run` returns evidence only (`PASS` is a status, not
  authority).
- [ ] `human.decide` is the only RPC that returns "accepted"-class
  semantics; the canonical transition requires an explicit
  HumanDecision envelope.

## 3. Event stream treated as canonical state

- [ ] `Kiln.Activity.Hub` holds NO authoritative state (only
  subscription registry).
- [ ] `Kiln.RPC.Handlers.Activity.handle/3` returns canonical state
  derived from `Kiln.Restart.reconstruct/1`, not from any cached
  notification.
- [ ] `products/temper/src/live.ts` re-queries canonical state on
  every notification.

## 4. Client cache becoming authority

- [ ] `Temper.currentModel` is the only Temper-side cache; it is
  replaced wholesale on every resync (no partial mutation).
- [ ] `Temper.lastObservedRevision` is a hint, not authoritative.

## 5. Session identity tied to transport / process

- [ ] `session_id` (ses_<32hex>) is generated by `Kiln.Domain.Id`,
  never derived from a Temper PID / daemon PID / WS connection /
  hostname / terminal.
- [ ] `client_id` (Temper-only) is NEVER persisted in the journal
  and never used for authorization.
- [ ] `subscription_id` is a correlation handle only.

## 6. Scope widening

- [ ] `Kiln.RPC.Router.@scopes` (router.ex:26-43) contains the same
  method-to-scope mapping as WP-08 PROVEN; no method accepts a
  scope wider than required.
- [ ] `Kiln.Service.verify_token/1` performs exact-match (not
  prefix-match, not superset-match).
- [ ] No new handler returns 200 for a method whose required scope
  is missing or wrong.

## 7. Authorization transfer

- [ ] `Kiln.RPC.Handlers.Patch.handle/3` does not accept an
  authorization decision from the caller that bypasses the existing
  PatchService decision validation.
- [ ] `human.decide` does not infer authorization from any source
  other than the operator's explicit envelope.
- [ ] `worker.propose` does not accept an assignment that overrides
  the bounded eligibility check.

## 8. Duplicate mutation on retry

- [ ] `Kiln.Workflow` (workflow.ex:849-914) preserves replay-by-key
  semantics from WP-08 PROVEN.
- [ ] `Kiln.RPC.Handlers.Patch.handle/3` honors envelope-level and
  params-level `idempotency_key` + `request_digest`.
- [ ] `Kiln.RPC.Handlers.Worker` / `Verify` / `Review` /
  `HumanDecision` all forward idempotency correctly.

## 9. Unknown-effect replay

- [ ] `PatchService.recover/3` (patch_service.ex:285-307) is the
  only recovery surface; it observes the repository BEFORE accepting
  caller-supplied state.
- [ ] `Kiln.Restart.reconstruct/1` (restart.ex:46-58) classifies
  nonterminal operations as `:orphaned` Run + `:unknown` Operation
  without appending journal rows (WP-08 PROVEN).

## 10. Raw Journal representation leaking into public protocol

- [ ] No `Kiln.RPC.Handlers.*` returns the raw Journal entry shape
  to the client.
- [ ] No `Kiln.Activity.Hub` notification carries the raw entry.
- [ ] `Kiln.RPC.Handlers.Activity.handle/3` returns the
  reconstructed projection digest, not the journal row contents.

## 11. Stale event rollback

- [ ] `products/temper/src/stream.ts` `processNotification/1`
  discards notifications with `revision < lastObservedRevision`.
- [ ] Test `live.test.ts` "ActivityStream discards stale
  notifications" PROVES this.

## 12. Missed-event corruption

- [ ] `products/temper/src/live.ts` `resync/1` re-queries canonical
  state via `project.open` after every notification and on every
  reconnect.
- [ ] Test `live.test.ts` "ActivityStream triggers resync on revision
  gap" PROVES this.

## 13. Test-only acceptance paths

- [ ] No test in `products/kiln/test/kiln/` returns success without
  going through the bounded Store.
- [ ] No test in `products/temper/test/` bypasses the daemon RPC
  (every Temper test mocks `fetch`, never invents success).
- [ ] `integration/scenarios/wp-09-temper-rpc/run.sh` uses real curl
  + real daemon; no fake reset.

## 14. Fake WebSocket behavior

- [ ] `products/kiln/test/kiln/activity_hub_test.exs` exercises the
  real Hub GenServer.
- [ ] `products/temper/test/live.test.ts` mocks `fetch` but exercises
  the real notification logic.

## 15. Fixture-only E2 proof

- [ ] The five-task driver
  (`integration/scenarios/wp-09-five-tasks/run.py`) creates real git
  repos and asserts real file contents post-flow.
- [ ] The integration scenario
  (`integration/scenarios/wp-09-temper-rpc/run.sh`) spawns a real
  `mix invariant serve` subprocess and asserts HTTP responses.

## 16. Reviewer self-approval

- [ ] `Kiln.RPC.Handlers.Review.handle/3` forwards the bounded
  reviewer-vs-implementer digest check from `Kiln.Review.build/9`
  (m9_review.ex:90-95). Test
  `m12_d_handlers_test.exs:review.propose with reviewer==implementer
  digest is rejected` PROVES the rejection.

## 17. HumanDecision inference

- [ ] No RPC handler except `human.decide` returns
  accepted/rejected semantics.
- [ ] `Kiln.RPC.Handlers.HumanDecision.handle/3` requires an
  explicit `decision` field with bounded values.

## 19. P2 journaling bypass

- [ ] `Kiln.RPC.Handlers.Patch.handle/3` uses
  `Kiln.Store.Journal.commit/4` to record intent + observation.
- [ ] No other RPC handler bypasses the bounded journal.
- [ ] The P2 production-intent-journaling pattern is the SAME shape
  as `Kiln.Test.JournalBuilder` uses
  (test/support/journal_builder.ex:108-139); no new entry types
  introduced.

## 20. Accidental distributed-system scope expansion

- [ ] No new GenServer, no new supervisor tree, no new distributed
  table.
- [ ] `Kiln.Activity.Hub` is a single named GenServer (no
  clustering).
- [ ] `Kiln.Daemon` supervisor is unchanged in shape.

## Reviewer disposition template

Each finding must be classified as one of:

```
FIX_REQUIRED  |  ACKNOWLEDGED (no fix)  |  FALSE_POSITIVE
```

with file:line + reasoning.

After all findings are dispositioned, the reviewer must independently
verify each fix by re-reading the code and (where applicable) re-running
the bounded test that proves the property.

Final verdict:

```
WP-09 REVIEW = PASS  |  PASS_WITH_FOLLOWUPS  |  BLOCK
```

only if the 20-item checklist above is fully dispositioned with
file:line evidence.
