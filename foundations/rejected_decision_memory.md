# Rejected-Decision Memory

Status: draft

Projects repeatedly waste time when an intentionally rejected idea returns as if it were new. Preserve durable rejections so future triage can distinguish reconsideration from forgotten history.

## What belongs here

Record a rejection when:

- the proposal is genuinely out of scope or conflicts with a durable product/architecture decision;
- the reason is substantive and expected to remain useful;
- similar requests are likely to recur.

Do not record:

- something that already exists;
- a temporary deferral caused only by schedule/capacity;
- an unresolved idea still under investigation.

## Record by concept

Group repeated requests around the rejected concept rather than creating one record per request.

Capture:

- concept name;
- current decision;
- durable reason/evidence;
- prior requests or discussions;
- reconsideration triggers.

## Triage behavior

When a new request resembles a prior rejection:

1. surface the prior decision and reason;
2. ask whether the underlying conditions have changed;
3. if unchanged, link the new request into the existing record;
4. if changed, explicitly supersede or remove the rejection before proceeding.

## Principle

A closed issue is history. A rejected-decision record is institutional memory.
