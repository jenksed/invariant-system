# Stateful Learning Workspace

Use for learning that should persist across multiple sessions rather than producing a one-off explanation.

## Persistent state

Maintain only useful learning state:

- **Mission** — why the learner wants this capability and what real-world use defines relevance.
- **Trusted resources** — primary/high-quality references used to ground instruction.
- **Learning records** — durable insights, misconceptions corrected, demonstrated capabilities, and mission changes.
- **Reference artifacts** — compressed cheatsheets/glossaries/procedures intended for repeated use.
- **Lessons/practice** — tightly scoped learning units.
- **Notes** — teaching preferences and temporary observations.

## Learning model

Distinguish:

- knowledge acquisition;
- skill acquisition through feedback;
- long-term retention through retrieval/spacing/interleaving;
- real-world judgment learned through authentic practice/community.

Do not mistake immediate fluency for durable mastery.

## Session selection

Choose the next lesson based on:

1. mission relevance;
2. prior learning records;
3. current demonstrated capability;
4. the learner's next achievable stretch.

Prefer one tangible win per lesson.

## Feedback loops

Skills require feedback. Use quizzes, labs, simulations, code execution, or real-world exercises with immediate observable feedback where possible.

Knowledge claims should be grounded in trusted sources rather than relying solely on model memory.

## Relationship to existing Arsenal learning assets

Use this workspace as the persistent container. `learning_session_designer`, `socratic_technical_tutor`, `session_to_study_guide`, and `skill_to_portfolio_lab_architect` provide individual session/artifact capabilities inside it.
