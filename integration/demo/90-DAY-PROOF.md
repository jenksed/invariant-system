# 90-Day Integrated Proof

## Thesis

An ordinary user can ask Loadout to understand and change a repository; the capability can improve as Arsenal methods evolve; and Kiln can preserve truthful execution across model replacement, restart, and evidence invalidation.

## Scenario

1. Arsenal has a qualified Repository Recon method record with bounded evidence.
2. Loadout exposes “Understand this repository” and “Fix this failing test” as stable capabilities.
3. Loadout compiles the Goal into a Work Envelope bound to repository state.
4. MiniMax M3 agent A begins the work through Kiln.
5. Agent A stops or crashes after observable effects.
6. Agent B resumes using the same durable work state without rediscovering the project from zero.
7. Repository state changes after an earlier verification result.
8. Kiln invalidates stale evidence and prevents a false-ready state.
9. The required gate reruns against current state.
10. Kiln returns a Run Result Envelope with effects, evidence, unknowns, and readiness.
11. Loadout presents the truthful result without exposing unnecessary substrate complexity.
12. A reviewed Learning Observation returns method friction and failure data to Arsenal.

## Success measures

- Capability contract unchanged across at least one method swap.
- Two agent sessions or models complete one continuous work record.
- Restart does not lose known effects or authority state.
- Stale evidence is deterministically rejected.
- User can inspect why completion is blocked or ready.
- No product imports another product's internal ontology.
- The complete demonstration fits within five minutes after setup.

## Failure conditions

- The demo requires an architecture lecture to appear valuable.
- Loadout presents simulated evidence as real.
- Kiln accepts green output detached from current state.
- Arsenal becomes a required online runtime service.
- A method swap breaks the user-level Capability contract.
- Operator ceremony costs more than rerunning the work manually.
